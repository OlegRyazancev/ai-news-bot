## 0. Foundation / базовая инфраструктура

**Статус:** ✅ Завершено

**Цель:** Создать рабочую основу приложения на Node.js и TypeScript с конфигурацией, логированием, Prisma и локальной PostgreSQL.

**Критерий завершения:** Проект успешно собирается и проходит lint, Prisma Client генерируется, PostgreSQL доступен, а актуальная Prisma-схема применена к базе.

**Основные результаты:**
- Каркас Telegram-бота и точка входа с graceful shutdown.
- Валидация окружения и уровневое логирование.
- Prisma-схема основных сущностей и подключение PostgreSQL.
- Docker-конфигурация приложения и базы данных.

**Зависимости:** Нет.

## 1. Telegram runtime

**Статус:** 🟡 В работе

**Цель:** Подтвердить работу персонального бота с реальным Telegram API в режиме long polling и связать запуск пользователя с персистентностью.

**Критерий завершения:** Бот запускается с реальным токеном, отвечает на `/start` в Telegram, а пользователь и его начальные настройки сохраняются в PostgreSQL; результат проверен в runtime.

**Основные результаты:**
- Runtime-проверенный запуск через long polling.
- Проверенные базовые команды `/start`, `/help`, `/settings` и `/latest`.
- Upsert пользователя и начальных настроек при `/start`.

**Зависимости:** Этап 0; действующий Telegram Bot Token.

## 2. Сбор новостей

**Статус:** ⬜ Запланировано

**Цель:** Автоматически получать новости об AI/LLM из выбранных доверенных RSS/API-источников.

**Критерий завершения:** Настроенные источники опрашиваются автоматически, а полученные статьи передаются в дальнейший поток обработки; сбор подтверждён в runtime.

**Основные результаты:**
- Определённый набор доверенных источников.
- Сервис получения и нормализации новостей из RSS/API.
- Регулярный запуск сбора.

**Зависимости:** Этап 0; выбор источников и механизма планирования.

## 3. Хранение и дедупликация

**Статус:** ⬜ Запланировано

**Цель:** Надёжно сохранять собранные статьи в PostgreSQL без повторов и предоставлять доступ к свежим материалам.

**Критерий завершения:** Статьи сохраняются в `NewsArticle`, повторная обработка того же URL не создаёт дубликат, а `/latest` возвращает реальные данные из базы; поведение проверено в runtime.

**Основные результаты:**
- Персистентность нормализованных статей.
- URL-based дедупликация.
- Команда `/latest` на данных PostgreSQL.

**Зависимости:** Этапы 1–2; PostgreSQL и Prisma.

## 4. LLM-обработка

**Статус:** ⬜ Запланировано

**Цель:** Обогащать статьи краткими резюме, оценкой важности и тематической категоризацией.

**Критерий завершения:** Выбранный LLM-провайдер обрабатывает реальные сохранённые статьи, а результаты суммаризации и классификации доступны последующим этапам; интеграция проверена в runtime.

**Основные результаты:**
- Абстракция и подключение LLM-провайдера.
- Суммаризация статей.
- Оценка важности и тематическая классификация.

**Зависимости:** Этап 3; решение по LLM-провайдеру.

## 5. Ежедневный дайджест

**Статус:** ⬜ Запланировано

**Цель:** Формировать и доставлять пользователю утреннюю сводку AI-новостей за последние 24 часа.

**Критерий завершения:** Дайджест автоматически создаётся по расписанию из обработанных статей, сохраняется в `NewsDigest` и доставляется в Telegram; полный цикл проверен в runtime.

**Основные результаты:**
- Формирование дайджеста за последние 24 часа.
- Планировщик ежедневного запуска.
- Сохранение истории и доставка в Telegram.

**Зависимости:** Этапы 1, 3–4; решение по scheduler.

## 6. Breaking News

**Статус:** ⬜ Запланировано

**Цель:** Отдельно доставлять важные новости вскоре после их обнаружения, не дожидаясь ежедневного дайджеста.

**Критерий завершения:** Новость, прошедшая порог важности, автоматически отправляется пользователю при очередном цикле сбора; доставка проверена в runtime.

**Основные результаты:**
- Отбор новостей по важности.
- Near-real-time доставка отдельных алертов.
- Интеграция с циклом сбора и Telegram Delivery.

**Зависимости:** Этапы 2–4; механизм планирования сбора.

## 7. Закреплённая шпаргалка по AI-моделям

**Статус:** ⬜ Запланировано

**Цель:** Поддерживать одно закреплённое сообщение с актуальной подборкой популярных AI-моделей по категориям.

**Критерий завершения:** Бот создаёт и закрепляет шпаргалку, а при обновлении редактирует существующее сообщение; механизм проверен в Telegram runtime.

**Основные результаты:**
- Категории coding, reasoning, fast, cheap и free.
- Генерация содержимого шпаргалки.
- Обновление одного закреплённого сообщения на месте.

**Зависимости:** Этапы 1 и 4; решения по источнику содержимого и механизму обновления сообщения.

## 8. Q&A по истории новостей

**Статус:** ⬜ Запланировано

**Цель:** Позволить пользователю задавать вопросы по накопленной истории AI-новостей.

**Критерий завершения:** Команда `/ask` отвечает на вопросы на основе сохранённых материалов, а полный запрос к истории и ответ проверены в runtime.

**Основные результаты:**
- Поиск релевантных материалов в истории.
- LLM-ответ на основе найденных новостей.
- Telegram-интерфейс `/ask`.

**Зависимости:** Этапы 1, 3–4; достаточная история сохранённых новостей.

## 9. Deployment / эксплуатация

**Статус:** 🟡 В работе

**Цель:** Обеспечить воспроизводимый запуск и устойчивую эксплуатацию бота и PostgreSQL в Docker.

**Критерий завершения:** Production-образ бота успешно собирается, bot и PostgreSQL запускаются через Docker Compose, а работа Telegram polling и базы подтверждена в контейнерном runtime.

**Основные результаты:**
- Проверенная сборка production Docker image.
- Проверенный совместный запуск bot и PostgreSQL через Docker Compose.
- Определённые эксплуатационные решения для логирования, мониторинга и резервного копирования.

**Зависимости:** Этап 1; Docker Engine; решения по эксплуатации.
