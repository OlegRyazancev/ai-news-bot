# /stage-close Command

## Назначение

Проверить Definition of Done текущего крупного этапа и либо закрыть его на основании фактов, либо показать незавершённые обязательные пункты.

## Workflow

### 1. Определить текущий этап

- Прочитай `AGENTS.md` и обязательные context-файлы.
- Определи этап по разделу **«Текущий фокус»** канонического `docs/ROADMAP.md`.
- Сверь его критерий завершения, зависимости и фактический статус.

### 2. Найти checklist

- Найди единственный checklist этапа в `docs/checklists/` по его двузначному номеру.
- Если checklist отсутствует, не закрывай этап: сообщи об ошибке процесса и предложи сначала выполнить `/stage-start`.
- Не создавай новый checklist во время закрытия только ради формального прохождения процесса.

### 3. Сверить реализацию

Сопоставь фактическую реализацию с:

- checklist;
- критерием завершения `docs/ROADMAP.md`;
- `docs/CURRENT_STATE.md`;
- `docs/BACKLOG.md`;
- `docs/ARCHITECTURE.md` и `docs/DECISIONS.md`;
- релевантным кодом.

Для каждого значимого результата используй один из статусов:

- `Verified`;
- `Build-Verified`;
- `Runtime-Verified`;
- `Not Verified`;
- `Not Applicable`.

### 4. Выполнить автоматические проверки

Как минимум выполни:

```bash
npm run build
npm run lint
```

Запусти тесты, если они существуют или требуются checklist/этапом. Не заменяй проваленные или отсутствующие проверки успешной сборкой.

### 5. Проверить Runtime Verification

- Runtime-пункт отмечается выполненным только после фактической проверки.
- Build Verification не доказывает работу Telegram, БД, внешнего API, UI или другой интеграции.
- Если требуется действие пользователя во внешней системе, сформируй точный runtime checklist и дождись фактического результата.
- До получения результата не обновляй статус этапа на `✅ Завершено`.

### 6. Проверить Decision Gate и Definition of Done

Убедись, что:

- обязательная реализация завершена;
- build, lint и применимые тесты проходят;
- обязательные runtime-проверки выполнены;
- все обязательные пункты checklist закрыты;
- нет незадокументированных значимых архитектурных решений;
- документация готова к синхронизации;
- `git diff` просмотрен.

### 7. Обработать результат

Если обязательные пункты не выполнены:

- не меняй статус этапа на `✅ Завершено`;
- перечисли незакрытые пункты и их фактические статусы;
- укажи конкретные следующие действия;
- не маскируй отсутствие Runtime Verification успешным build.

Если все обязательные пункты выполнены:

1. Отметь checklist завершённым.
2. Синхронизируй `docs/CURRENT_STATE.md`.
3. Синхронизируй `docs/BACKLOG.md`.
4. Сначала обнови канонический `docs/ROADMAP.md`.
5. Затем синхронизируй `docs/ROADMAP_VISUAL.md`.
6. Обнови `docs/DECISIONS.md`, если появились новые принятые решения.
7. Проверь `git diff`.

### 8. Выдать Stage Close Report

Используй формат:

```text
Stage:
Result:
Build:
Lint:
Tests:
Runtime:
Checklist:
Docs synchronized:
Remaining issues:
Next stage / milestone:
```

## Rules

- Не закрывай этап без checklist и выполненного критерия завершения.
- Не утверждай Runtime-Verified без фактической runtime-проверки.
- Не выполняй commit или push без явного запроса пользователя.
